# v2.4 WorkManager 与本地通知规格

> **关联 Issue**：[约定 v2.4 WorkManager 与本地通知规格](https://github.com/Zoti321/c2c-market/issues/24)  
> **锁定日期**：2026-09-19  
> **状态**：已锁定  
> **依据**：[v2.3 结算 / 订单快照](v2.3-address-crud.md)、[ADR-0003 游客 Mock 结算](../adr/0003-guest-mode-mock-checkout.md)

## 目标

在 Mock 下单成功后，用 **WorkManager** 延迟触发 **本地通知**，模拟「订单进入配送」；点击通知打开 App 并跳转 **订单详情**。仅本地通知，**无 FCM / 远端 Push**。

---

## 1. 业务场景

| 项 | 决定 |
|----|------|
| 触发 | `placeOrder` **成功**后立即调度 Worker |
| 语义 | Mock 物流提醒，**不改变** `OrderStatus`（仍为 `COMPLETED`） |
| 延迟 | **15 秒** `OneTimeWorkRequest`（便于手工验收；常量 `ORDER_NOTIFICATION_DELAY_SECONDS`） |
| 约束 | **无网络**要求（`NetworkType.NOT_REQUIRED`） |
| 去重 | `enqueueUniqueWork("order_ship_notify_{orderId}", REPLACE, request)` |

---

## 2. WorkManager 架构

```
OrderRepositoryImpl.placeOrder(...)
  → OrderNotificationScheduler.schedule(orderId, displayNumber)
       → WorkManager.enqueueUniqueWork(...)

OrderShippedNotificationWorker (CoroutineWorker + @HiltWorker)
  → NotificationHelper.showOrderShipped(...)
```

### 2.1 接口

```kotlin
interface OrderNotificationScheduler {
    fun schedule(orderId: Long, orderNumber: String)
}
```

- 实现类 `WorkManagerOrderNotificationScheduler` `@Singleton`，注入 `WorkManager`
- **`OrderRepositoryImpl`** 在事务成功、`placeOrder` 返回前调用 `schedule`（不阻塞 UI；enqueue 同步即可）

### 2.2 Worker

**`OrderShippedNotificationWorker`**：

- 基类：`CoroutineWorker`
- 注解：`@HiltWorker` + `@AssistedInject`
- Input：`KEY_ORDER_ID: Long`，`KEY_ORDER_NUMBER: String`
- `doWork()`：
  1. 若 `NotificationHelper` 判定无通知权限 → `Result.success()`（静默跳过，不失败重试）
  2. 展示本地通知
  3. `Result.success()`

- **不重试**：失败（异常）→ `Result.failure()`；不链式 RetryPolicy（学习项目保持简单）

### 2.3 Hilt / Application

- 依赖：`androidx.work:work-runtime-ktx`、`androidx.hilt:hilt-work`
- `C2CApplication` 实现 `Configuration.Provider`，注入 `HiltWorkerFactory`
- Manifest：`androidx.startup.InitializationProvider` 下禁用默认 WorkManager 初始化（Hilt 标准做法）或使用 `Configuration.Provider` 模式（implement 按 Hilt 文档二选一，推荐 **Configuration.Provider**）

## 3. 本地通知

### 3.1 权限

- Manifest：`POST_NOTIFICATIONS`（API 33+）
- **请求时机**：`CheckoutScreen` 在用户点击 **「确认下单」** 前，若 API ≥ 33 且未授权，先 `rememberLauncherForActivityResult(RequestPermission)`；拒绝仍允许下单，但不调度 Worker（`schedule` 内检查权限，无权限则 return）

### 3.2 NotificationChannel

| 项 | 值 |
|----|-----|
| channelId | `order_updates` |
| 名称 | 订单通知 |
| 重要性 | `IMPORTANCE_DEFAULT` |

- App 首次展示通知前创建 Channel（`NotificationHelper.ensureChannel`）

### 3.3 通知内容

| 项 | 值 |
|----|-----|
| title | Mock 配送提醒 |
| text | 订单 {orderNumber} 已模拟进入配送 |
| smallIcon | `@drawable/ic_notification`（implement 添加简单 vector） |
| notificationId | `orderId.toInt()`（FakeStore 规模下足够） |

### 3.4 点击行为

- `PendingIntent` → `MainActivity`，flags `FLAG_UPDATE_CURRENT | FLAG_IMMUTABLE`
- Extra：`MainActivity.EXTRA_ORDER_ID = orderId`
- `MainActivity` / `C2CNavHost`：若 intent 带 `EXTRA_ORDER_ID`，`LaunchedEffect` 内 `navController.navigate(Routes.order(id))` 并 `clearExtra`

- **不做** App Links / Deep Link URL scheme

## 5. 用户可见行为

1. 结算成功 → 跳转订单详情（既有行为）
2. **约 15 秒后**（App 前台或后台均可）→ 系统通知栏出现 Mock 配送提醒
3. 点击通知 → 打开 App 到该订单详情
4. 拒绝通知权限 → 下单正常，无通知

## 7. v2.4 明确不做

- FCM / 远端 Push
- 周期性 Worker（PeriodicWorkRequest）
- 通知操作按钮（「查看物流」等）
- 根据订单状态机多阶段通知
- BootReceiver 手动重调度（WorkManager 自带持久化 OneTimeWork 即可）
- 修改 `OrderStatus` 枚举
- 前台 Service
- 购物车 abandoned 提醒
