游客用户可 **增删改查收货地址**（Room SSOT），在 **结算页选择地址** 后 Mock 下单；订单 **快照** 收货信息，详情可回看。

## 1. 领域模型

### 1.1 Address（domain）

```kotlin
data class Address(
    val id: Long,
    val receiverName: String,
    val phone: String,
    val region: String,        // 省市区，自由文本，如「广东省深圳市南山区」
    val detail: String,        // 街道门牌等
    val isDefault: Boolean,
    val updatedAt: Instant,
) {
    fun formatted(): String = "$region $detail"
}
```

### 1.2 Room Entity

**`AddressEntity`**（表 `addresses`）：

| 列 | 类型 | 说明 |
|----|------|------|
| `id` | INTEGER PK auto | |
| `receiverName` | TEXT | |
| `phone` | TEXT | 11 位手机号 |
| `region` | TEXT | |
| `detail` | TEXT | |
| `isDefault` | INTEGER (0/1) | 同一游客仅 **一条** default |
| `updatedAt` | INTEGER | epoch millis |

- 游客仅本地一个身份，**不按 guestId 分表**（与 MVP 订单一致，隐含单用户）
- DB Migration：在 v2.1/v2.2 之后 **+1 版本**（implement 时链接实际 migration 链）

### 1.3 订单地址快照

**`OrderEntity` 扩展**（Migration 同批）：

| 新增列 | 类型 | 说明 |
|--------|------|------|
| `shippingReceiverName` | TEXT | 下单时快照 |
| `shippingPhone` | TEXT | |
| `shippingAddress` | TEXT | `region + " " + detail` 合并字符串 |

- 历史 MVP 订单（迁移前）：三列 **NULL** → 详情 UI 显示「未填写收货地址」
- **`Order` domain** 增加可选 `shipping: ShippingInfo?`

```kotlin
data class ShippingInfo(
    val receiverName: String,
    val phone: String,
    val address: String,
)
```

## 2. 地址 CRUD

### 2.1 入口（我的 Tab）

- 在「我的挂牌」与「我的订单」之间增加 **ListItem「收货地址」**（leading `LocationOn` icon，trailing 箭头）
- 点击进入 `AddressListScreen`

### 2.2 地址列表（`AddressListScreen`）

| 能力 | 行为 |
|------|------|
| 展示 | 全部地址，默认地址 **置顶**；次排序 `updatedAt DESC` |
| 默认标记 | 默认项 headline 旁 `AssistChip`「默认」 |
| 新增 | FAB 或 TopAppBar action **+** → `AddressFormScreen`（create） |
| 编辑 | 点击行 → `AddressFormScreen`（edit） |
| 删除 | 行内删除图标 → 确认 Dialog → 删除；若删默认且仍有其他地址，**最早 updated 的升为默认** |
| 设默认 | 非默认项 trailing「设为默认」TextButton |
| 空态 | EmptyContent + 「添加地址」按钮 |

### 2.3 地址表单（`AddressFormScreen`）

| 字段 | 校验 |
|------|------|
| 收货人 | 非 blank，≤ 20 字 |
| 手机号 | `^1[3-9]\\d{9}$` |
| 省市区 | 非 blank，≤ 50 字 |
| 详细地址 | 非 blank，≤ 100 字 |
| 设为默认 | `Switch`（新建默认 **开**；编辑保持当前） |

- 保存 → `AddressRepository.create/update` → Snackbar + pop
- **首条地址**创建时强制 `isDefault = true`

### 2.4 Repository

```kotlin
interface AddressRepository {
    fun observeAll(): Flow<List<Address>>
    fun observeDefault(): Flow<Address?>
    suspend fun getById(id: Long): Result<Address>
    suspend fun create(input: AddressInput): Result<Address>
    suspend fun update(id: Long, input: AddressInput): Result<Address>
    suspend fun delete(id: Long): Result<Unit>
    suspend fun setDefault(id: Long): Result<Unit>
}
```

- `setDefault` / `create(默认)` / `update` 在 **Transaction** 内清除其他 `isDefault`
- UI 不直连 DAO

## 3. 结算集成

### 3.1 结算页 UI 增量（`CheckoutScreen`）

在商品列表 **上方** 增加 **收货地址卡片**：

```
┌─────────────────────────────┐
│ 收货地址                    │
│ 张三  138****8000           │
│ 广东省深圳市南山区 xx 路    │  ← 单行省略，点击换地址
└─────────────────────────────┘
```

| 状态 | 行为 |
|------|------|
| 有默认地址 | 展示默认；若用户曾在本次会话换过址，展示 **选中项** |
| 有地址无默认 | 展示第一条（不应出现；Repository 保证有则必有 default） |
| **无任何地址** | 卡片文案「请添加收货地址」+ 点击 → `AddressFormScreen` create；**确认下单 disabled** |
| 换地址 | 点击卡片 → `AddressPickerBottomSheet`（地址列表 + 选中勾 + 「管理地址」链到 list） |

### 3.2 CheckoutViewModel

```kotlin
val addresses: StateFlow<List<Address>>
val selectedAddressId: StateFlow<Long?>
val selectedAddress: StateFlow<Address?>
val canPlaceOrder: StateFlow<Boolean>  // selectedAddress != null
```

- 初始化：`selectedAddressId` = 默认地址 id（若有）
- `selectAddress(id)`：更新选中（**仅内存**，不写 DataStore；进程内有效）
- `placeOrder()`：无选中地址 → 不调用；有则 `orderRepository.placeOrder(shipping = selected.toShippingInfo())`

### 3.3 placeOrder 变更

```kotlin
// OrderRepository
suspend fun placeOrder(shipping: ShippingInfo): Result<Order>
```

- `OrderRepositoryImpl`：写入 `OrderEntity` 三列快照 + 既有 line items + 清购物车
- 仍 Mock，无物流 API

## 9. v2.3 明确不做

- 地图选点 / GPS 定位
- 省市区三级联动 picker（自由文本即可）
- 地址校验（快递可达性）
- DataStore 持久化「上次选中地址」（进程内选中足够）
- 多收货人 / 地址簿同步云端
- 结算页 **手动输入** 地址（必须走地址库）
